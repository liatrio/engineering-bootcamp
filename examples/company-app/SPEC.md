# Company App Specification

This is the single source of truth for the Company app that Chapter 3 of the bootcamp is built around. Every service, test, compose file, and doc page follows it. If code and this file disagree, fix one of them in the same change.

## Services

| Service | Language / framework | Container port | Host port (compose) | Path prefix |
| --- | --- | --- | --- | --- |
| `frontend-proxy` | nginx | 8080 | **8080** | routes everything below |
| `web` | React + TypeScript (Vite build, served by nginx) | 8080 | — | `/` |
| `employees-service` | .NET 10, ASP.NET Core controllers, EF Core, PostgreSQL | 8080 | 5101 | `/api/employees` |
| `projects-service` | Python 3.13, FastAPI, SQLAlchemy 2, PostgreSQL | 8000 | 5102 | `/api/projects` |
| `assignments-service` | .NET 10 (**built by learners**, reference in `milestones/`) | 8080 | 5103 | `/api/assignments` |
| `notifications-service` | Go, `net/http`, `amqp091-go` | 8080 | 5104 | `/api/notifications` |

**Infrastructure:**

| Component | Image | Ports (host) | Notes |
| --- | --- | --- | --- |
| `postgres` | `postgres:17` | 5433 → 5432 | One server, one database per service: `employees`, `projects`, `assignments`. Created by `infra/postgres/init.sql`. |
| `rabbitmq` | `rabbitmq:4-management` | 5672, 15672 | Management UI at http://localhost:15672 (guest/guest). |
| `flagd` | `ghcr.io/open-feature/flagd` (pinned) | 8013 | Reads `infra/flagd/flags.flagd.json`. |
| `otel-lgtm` | `grafana/otel-lgtm` (pinned) | 3001 → 3000, 4317, 4318 | Grafana on **3001** (the docs site uses 3000). |
| `load` (profile `load`) | `grafana/k6` | — | Runs `infra/k6/load.js` against the proxy. |
| `pact-broker` (profile `broker`) | `pactfoundation/pact-broker` | 9292 | Stretch only. |

Each service serves its full path itself (for example `employees-service` answers `GET /api/employees`). So the proxy passes paths through unchanged, and a service can be called directly on its host port with the same path.

**Proxy routes:**
- `/` → `web:8080`
- `/api/employees` → `employees-service:8080`
- `/api/projects` → `projects-service:8000`
- `/api/assignments` → `assignments-service:8080`. Returns 502 until learners add the service. The web Assignments page handles that.
- `/api/notifications` → `notifications-service:8080`
- `/otlp/` → `otel-lgtm:4318/`, for browser telemetry with no CORS.

The proxy uses a Docker DNS `resolver` with variables in `proxy_pass`, so a missing upstream (assignments) gives a 502 instead of stopping nginx from starting.

## Conventions for every backend service

- **Configuration comes from environment variables only.** No URLs, credentials, or ports are hard-coded. .NET uses the options pattern bound from configuration.

  | Variable | Meaning | Default |
  | --- | --- | --- |
  | `PORT` | Listen port | 8080 (Python: 8000) |
  | `DATABASE_URL` | PostgreSQL connection. .NET: `ConnectionStrings__Default` | required where the service has a database |
  | `RABBITMQ_URL` | `amqp://guest:guest@rabbitmq:5672/` | required where the service uses RabbitMQ |
  | `EMPLOYEES_URL` / `PROJECTS_URL` | Base URLs of other services (assignments only) | required |
  | `FLAGD_HOST` / `FLAGD_PORT` | flagd | `flagd` / `8013` |
  | `OTEL_SERVICE_NAME` | Set per service | the service name |
  | `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://otel-lgtm:4318` | — |
  | `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/protobuf` | — |
  | `SEED_DATA` | Insert seed rows on startup when the table is empty | `true` |
  | `ENABLE_PROVIDER_STATES` | Expose the Pact provider-state endpoint | `false` |
  | `AUTH_TOKEN` | When set, every `/api/*` request needs `Authorization: Bearer <token>`. Unset means no auth. Off in Chapter 3; Chapter 7.3 switches it on. | unset |

- **Health:**
  - `GET /healthz`: liveness. 200 `{"status":"ok"}` if the process is up. Checks nothing else.
  - `GET /readyz`: readiness. 200 only when the service's dependencies (database, RabbitMQ) are reachable, otherwise 503.
  - Neither endpoint needs auth.

- **IDs** are GUIDs (UUID v4), generated by the service. Timestamps are UTC ISO-8601 (`createdAt`, `updatedAt`).

- **JSON** uses camelCase.

- **Errors** are RFC 9457 Problem Details (`application/problem+json`): `type`, `title`, `status`, `detail`, and `errors` (a field → messages map) for validation failures.

  | Situation | Status |
  | --- | --- |
  | Validation failure | 400 |
  | Missing auth when `AUTH_TOKEN` is set | 401 |
  | Unknown ID | 404 |
  | Uniqueness or conflict | 409 |
  | Unexpected error | 500, with no stack trace in the body |

- **CRUD semantics:**
  - `POST` returns 201 with a `Location` header and the body.
  - `PUT` replaces every writable field and returns 200 with the body.
  - `DELETE` returns 204. Deleting an unknown ID returns 404.

  These match what a Terraform provider needs (Chapter 7.3): create, read by ID (`terraform import`), update, and delete.

- **OpenAPI:** each service commits its document at `openapi.yaml` in the service root, kept in sync with the code. .NET and FastAPI also serve it live: .NET at `/openapi/v1.json`, FastAPI at `/openapi.json`.

- **Container:** a multi-stage `Dockerfile` that runs as a non-root user, exposes the container port, and has no `HEALTHCHECK`, because compose defines health checks.

- **Telemetry:** OTLP over HTTP to `OTEL_EXPORTER_OTLP_ENDPOINT`, with traces, metrics, and logs. Logs are structured and include the trace ID.
  - **.NET:** the OpenTelemetry SDK configured in code:
    - `OpenTelemetry.Extensions.Hosting`, plus ASP.NET Core, HttpClient, and runtime instrumentation;
    - `Npgsql.OpenTelemetry` for database spans;
    - the `RabbitMQ.Client` 7.x built-in ActivitySource (`RabbitMQ.Client.*`), which injects W3C `traceparent` into message headers when publishing;
    - the OTLP exporter.
  - **Python:** zero-code `opentelemetry-instrument` with the FastAPI, SQLAlchemy, and logging instrumentations. **Never `--reload` or several workers when instrumented.**
  - **Go:** the SDK, with `otelhttp` for HTTP. Extraction from AMQP headers is **written by hand** with a `propagation.TextMapCarrier` over `amqp.Table`, decoding `[]byte` header values, because RabbitMQ.Client writes header values as bytes. Each message gets a consumer span (`SpanKindConsumer`) whose parent is the extracted context.
  - **Web:** `@opentelemetry/sdk-trace` (the successor to the deprecated `sdk-trace-web`) with fetch instrumentation, exporting to `/otlp/v1/traces` through the proxy. It propagates `traceparent` on `/api/*` calls, so a trace starts in the browser.

## Domain and APIs

Seed data uses fixed IDs, so tests, Pact provider states, and E2E tests can rely on them.

### Employees (`employees-service`)

```json
{ "id": "uuid", "name": "string (1–100)", "email": "string, valid, unique (case-insensitive)",
  "title": "string (1–100)", "department": "string (1–100)",
  "createdAt": "datetime", "updatedAt": "datetime" }
```

- `GET /api/employees` (optional `?department=`), `GET /api/employees/{id}`, `POST`, `PUT /api/employees/{id}`, `DELETE /api/employees/{id}`.
- A duplicate email returns 409.

**Seed:**

| id | name | email | title | department |
| --- | --- | --- | --- | --- |
| `11111111-1111-4111-8111-111111111111` | Ada Lovelace | ada@example.com | Principal Engineer | Engineering |
| `22222222-2222-4222-8222-222222222222` | Grace Hopper | grace@example.com | Engineering Manager | Engineering |
| `33333333-3333-4333-8333-333333333333` | Alan Turing | alan@example.com | Data Scientist | Research |

Code layout follows app-dev-forge: vertical slices under `Features/Employees/` (entity, configuration, DTOs, service, controller), with shared foundation code under `Infrastructure/`.

### Projects (`projects-service`)

```json
{ "id": "uuid", "name": "string (1–100), unique (case-insensitive)", "description": "string (0–500)",
  "startDate": "date (YYYY-MM-DD)", "status": "planned | active | completed",
  "createdAt": "datetime", "updatedAt": "datetime" }
```

- `GET /api/projects`, `GET /api/projects/{id}`, `POST`, `PUT /api/projects/{id}`, `DELETE /api/projects/{id}`.
- A duplicate name returns 409.

**Seed:**

| id | name | status | startDate |
| --- | --- | --- | --- |
| `aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa` | Platform Modernization | active | 2026-01-05 |
| `bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb` | Customer Portal | planned | 2026-03-02 |
| `cccccccc-cccc-4ccc-8ccc-cccccccccccc` | Data Warehouse | completed | 2025-06-16 |

Layout: `app/` with `routers/`, `services/`, `repositories/`, `models.py` (SQLAlchemy), `schemas.py` (Pydantic), `config.py` (pydantic-settings), `main.py`.

### Assignments (`assignments-service`, learner-built; reference in `milestones/`)

```json
{ "id": "uuid", "employeeId": "uuid", "projectId": "uuid", "role": "string (1–100)",
  "allocationPercent": "integer 1–100", "startDate": "date", "endDate": "date | null",
  "createdAt": "datetime", "updatedAt": "datetime" }
```

- `GET /api/assignments` (optional `?employeeId=`, `?projectId=`), `GET /api/assignments/{id}`, `POST`, `PUT /api/assignments/{id}`, `DELETE /api/assignments/{id}`.
- An employee or project that doesn't exist in its service returns 400, with `errors.employeeId` or `errors.projectId`.
- The same employee and project assigned twice returns 409.
- If Employees or Projects is unavailable, the service returns 503 Problem Details.
- **Added in M3 by TDD (3.4.2), not in M2:**
  - an employee's total `allocationPercent` across overlapping assignments must be 100 or less (otherwise 409);
  - `endDate`, when set, must come after `startDate` (otherwise 400).

### Notifications (`notifications-service`)

- Consumes every event on the `company.events` exchange (binding key `#`, durable queue `notifications`).
- Keeps the latest 100 in memory. It's a read model, and losing it on restart is acceptable; the docs say so.
- `GET /api/notifications` returns the newest first:

  ```json
  [{ "id": "uuid", "type": "employee.created", "message": "Employee Ada Lovelace was created",
     "occurredAt": "datetime", "traceId": "hex or empty" }]
  ```

- `GET /healthz` and `/readyz`. Ready means connected to RabbitMQ.

## Events (RabbitMQ)

- Exchange: `company.events`, type `topic`, durable.
- Routing key = event type.
- Messages are JSON, persistent, with `content_type: application/json`.
- An envelope wraps every event:

```json
{ "eventId": "uuid", "type": "employee.deleted", "occurredAt": "datetime", "source": "employees-service",
  "data": { "...": "the entity or its id" } }
```

| Type | Publisher | `data` |
| --- | --- | --- |
| `employee.created`, `employee.updated` | employees-service | full employee |
| `employee.deleted` | employees-service | `{ "id": "uuid" }` |
| `assignment.created` | assignments-service | full assignment |

- Assignments consumes `employee.deleted` (queue `assignments.employee-deleted`) and deletes that employee's assignments.
- Publishing happens after the database commit. The dual-write gap is taught in 3.3.6; the outbox pattern is named but not built.

## Pact provider states

When `ENABLE_PROVIDER_STATES=true`, employees and projects expose `POST /_pact/provider-states` with the body `{"state": "...", "params": {...}, "action": "setup" | "teardown"}`. On `setup`, the service resets its tables to the seed data, then applies the state. Supported states:

| Service | State | Effect |
| --- | --- | --- |
| employees | `employees exist` | Seed data only |
| employees | `no employee with id {id} exists` | Seed data, and makes sure that ID is absent |
| projects | `projects exist` | Seed data only |
| projects | `no project with id {id} exists` | Seed data, and makes sure that ID is absent |

## Feature flags (flagd, `infra/flagd/flags.flagd.json`)

| Flag | Type | Default | Used by | Purpose |
| --- | --- | --- | --- | --- |
| `project-description-required` | boolean | `off` | projects-service | Release-flag example: when on, creating a project needs a description |
| `assignment-notifications` | boolean | `off` | assignments (M6) | Release flag: publish `assignment.created` |
| `assignments-writes` | boolean | `on` | assignments (M6) | Kill switch: off makes writes return 503 |
| `allocation-check` | boolean, with a fractional rollout | `off` | assignments (M6) | Percentage rollout of the allocation rule |

The starter's flag file contains only `project-description-required`. Learners add the others.

## Deliberate gaps (for each section's Practice step)

The starters are complete and best-practice, apart from these small, documented gaps. Each gap still passes the starter's CI, so leave it exactly as described. The doc page named in each row walks learners through closing it.

| Section | Service | Gap |
| --- | --- | --- |
| 3.3.2 | projects | `GET /api/projects` has no `?status=` filter |
| 3.3.3 | employees | `EmployeeService` calls `DateTime.UtcNow` directly instead of an injected `TimeProvider` |
| 3.4.2 | projects | No status-transition rule, and no test for one. Learners add, test-first: `planned → active → completed` only, never backwards; an invalid move returns 409. |
| 3.4.3 | employees | Service tests can't control timestamps (follows from 3.3.3); learners use `FakeTimeProvider` |
| 3.4.4 | employees | Component tests share **one static in-memory fake repository**, so results depend on test order. No test for `DELETE` of an unknown ID. |
| 3.4.5 | employees | Integration tests (Testcontainers PostgreSQL) don't cover the unique-email database constraint |
| 3.4.6 | web → projects | The Pact consumer covers `GET /api/projects` and `GET /api/projects/{id}`, but not `POST /api/projects`, which the UI uses |
| 3.4.7 | web | Playwright covers creating an employee, not creating a project |
| 3.4.8 | projects | Coverage threshold set to 80%; `services/project_service.py` has an untested error branch |
| 3.4.9 | projects | ruff runs a minimal rule set; learners enable `B` (bugbear) and fix what it finds (one finding is planted) |
| 3.5 | projects | No custom business metric (employees has `company.employees.created`; projects has nothing similar) |
| 3.5.3 | employees | `DELETE` creates no manual span around publishing the event (create and update do) |
| 3.6 | employees | No flag around event publishing. Learners add an ops flag, `employee-events`, as a kill switch. |

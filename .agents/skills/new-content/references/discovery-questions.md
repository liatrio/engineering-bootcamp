# Discovery questions

Ask these before drafting anything. Ask a few at a time, skip anything the user already answered, and do not write content until the answers are in.

## Intent

- What topic or tool is this about?
- After finishing, what should a learner be able to do or discuss?

## Audience

- What do learners already know?
- Which earlier content does this depend on? Name it so the new content can link back ("this differs from X, which you already know, in that...").

## Placement

Read `docs/_sidebar.md` first, then offer concrete options instead of asking open-ended.

- Which chapter fits? Is this a new page, or an addition to an existing page?
- What comes before and after it?
- If it goes in the middle of a chapter, say so: neighbors may need renumbering (see the `move-content` skill).

Never default to "end of chapter" or "end of section".

## Format

- Intro lesson, intro exercise, or challenge exercise? Recommend one based on the answers above and say why. The user can override. See the format table in `SKILL.md`.

## Exercise ideas (exercises only)

- Offer 2-3 scenarios to choose from, each in a sentence.
- Group or solo? Time budget?
- What environment is available: code under `examples/`, cloud accounts, local tooling?

## Source material

- Is there seed text, links, or vendor docs to build on?

## Quiz

- Suggest a quiz after the deliverables. Do not require one.

# Git Hooks and pre-commit

**Git hooks** are scripts that Git runs automatically at points in its workflow: before a commit is created (`pre-commit`), after it's created (`post-commit`), when the message is written (`commit-msg`), or before a push (`pre-push`). If a `pre-commit` or `pre-push` hook exits with an error, Git stops. Every repository has sample hooks in `.git/hooks/`.

Hooks **shift feedback left**. CI tells you about a problem minutes after you push; a hook tells you before the commit exists. Some problems are much cheaper to catch there:

- **Secrets.** Once a password or API key is committed and pushed, it's in the history for anyone with a clone. Removing it means rewriting history and rotating the secret anyway.
- **Noise.** Formatting fixes and lint fixes made after review turn into "fix lint" commits that clutter the history and the diff.

Hooks complement CI; they don't replace it. Anyone can skip them with `git commit --no-verify`, and anyone who never installed them doesn't run them at all. CI is the gate; hooks are the early warning.

## The pre-commit Framework

![pre-commit logo](img/pre-commit.png ':size=120px :class=img-shadow-center :alt= pre-commit logo')

Plain hooks have two problems: they live in `.git/hooks/`, which isn't versioned, so every teammate has to copy them by hand; and each one is a script you write and maintain. [pre-commit](https://pre-commit.com/) solves both:

- The configuration is a versioned file, `.pre-commit-config.yaml`, at the repository root. Every teammate runs `pre-commit install` once, and from then on the same checks run for everyone.
- Each entry points at a **hook repository** and a pinned version (`rev`). pre-commit downloads the tool into an isolated environment, so nobody needs the right version of ruff or gitleaks installed.
- It runs each hook only on the **staged files** that match it, so a commit that touches one Python file doesn't run the .NET formatter.
- A `repo: local` hook runs a command you already have, such as `dotnet format` or `npm run lint`, with no download.

### Keep hooks fast

A hook that takes a minute gets skipped with `--no-verify`, and then it checks nothing. Run checks that take seconds and look only at the changed files: formatters, linters, secret scanning, file hygiene. Leave tests, coverage, and builds to CI.

### Run the same checks as CI

When a hook and CI disagree, people stop trusting both. Make each hook run the same tool, version, and configuration as the CI job:

- pin the hook's `rev` to the version the service already uses (ruff in `pyproject.toml`, for example);
- let the tool read the service's own configuration (`pyproject.toml`, `.editorconfig`, `eslint.config.js`) instead of repeating settings in the hook;
- prefer `repo: local` hooks that call the same command CI calls.

> [!WARNING]
> A hook repository is code that runs on every developer's machine. Pin every `rev` to a release tag (or a commit SHA), use well-known sources, and review the change when you update one with `pre-commit autoupdate`.

## Exercise

### Example: M4's pre-commit configuration

Read M4's [`.pre-commit-config.yaml`](https://github.com/liatrio/engineering-bootcamp/tree/master/examples/company-app/milestones/M4-quality-automation/.pre-commit-config.yaml). For each hook, write down what it checks and which files it runs on. Then answer:

1. Why do the pact files skip `end-of-file-fixer`?
2. The ruff hook has no `args`. How does it know which rules to apply?
3. Why does `dotnet format` use `pass_filenames: false`?
4. Which hook has no equivalent in M4's CI workflow? Is that a gap?

### Practice: watch pre-commit block a secret

1. Install pre-commit, once per machine, with one of:

    ```bash
    pipx install pre-commit
    uv tool install pre-commit
    brew install pre-commit
    ```

2. Branch: `git switch -c chore/pre-commit`. Create `.pre-commit-config.yaml` with two hook repositories:

    ```yaml
    repos:
      - repo: https://github.com/pre-commit/pre-commit-hooks
        rev: v6.0.0
        hooks:
          - id: trailing-whitespace
          - id: end-of-file-fixer
      - repo: https://github.com/gitleaks/gitleaks
        rev: v8.30.1
        hooks:
          - id: gitleaks
    ```

3. Install the hooks into your clone with `pre-commit install`. It prints `pre-commit installed at .git/hooks/pre-commit`.
4. Create a file holding something shaped like a GitHub token, and try to commit it:

    ```bash
    echo "GITHUB_TOKEN=ghp_$(openssl rand -hex 18)" > leak.env
    git add leak.env
    git commit -m "add config"
    ```

    The `Detect hardcoded secrets` hook fails: gitleaks names the rule it matched (a GitHub personal access token), redacts the secret, and reports `leaks found: 1`. No commit is created. Remove the file with `git rm --cached leak.env && rm leak.env`.

5. Add a line ending in spaces to any text file and commit it. `trim trailing whitespace` fails and **fixes the file**. The fix isn't staged yet: run `git add` on the file and commit again. That's how every fixing hook works.
6. Run `pre-commit run --all-files` to check the whole repository. If a file is missing its final newline, for example an `openapi.yaml` you saved straight from `curl`, `end-of-file-fixer` adds it; commit those fixes. It also changes `web/pacts/web-projects-service.json`: undo that one with `git restore web/pacts`, because Pact rewrites the file on every test run. The Apply step excludes pact files from this hook.

### Apply: one configuration for the whole monorepo

Extend `.pre-commit-config.yaml` so each service gets the same checks as its CI job, and only when its files change.

1. **File hygiene.** Add `check-yaml` (with `--allow-multiple-documents`), `check-json`, `check-merge-conflict`, `check-added-large-files`, and `detect-private-key` to the `pre-commit-hooks` entry. Exclude `^.*/pacts/.*\.json$` from `end-of-file-fixer`: Pact writes those files, and the next test run would undo the fix. Exclude `.devcontainer/devcontainer.json` from `check-json`, because it contains comments.
2. **Python.** Add `https://github.com/astral-sh/ruff-pre-commit` with the hook `ruff-check`, `files: ^projects-service/`, and the `rev` matching ruff's version in `projects-service/pyproject.toml` (`v0.17.5` in the starter).
3. **.NET.** Add a `repo: local` hook with `language: system` that runs `dotnet format assignments-service/AssignmentsService.slnx --verify-no-changes` for `files: ^assignments-service/.*\.cs$`, with `pass_filenames: false`.
4. **Go.** Add a local hook for `^notifications-service/.*\.go$` that runs `gofmt -l` on the staged files and fails if it prints anything. `gofmt` always exits 0, so wrap it: `bash -c 'out=$(gofmt -l "$@"); [ -z "$out" ] || { echo "$out"; exit 1; }' --`.
5. **Web.** Add a local hook for `^web/` that runs `npm --prefix web run lint`, with `pass_filenames: false`.
6. **Check it.** Run `pre-commit run --all-files` until every hook passes. Then prove each language hook works: break formatting in one `.cs`, one `.go`, one `.py`, and one `.tsx` file, try to commit, and watch the right hook, and only that hook, fail. Undo the changes.
7. **Document it.** Put the two setup commands at the top of the config file as a comment, and add pre-commit to the **Commands** table in `AGENTS.md`. Add a rule to the **Rules** section: "Never commit with `--no-verify` to get past a hook. Fix what it found."
8. Open the pull request, and have every teammate run `pre-commit install` once it merges.

> Compare with M4's [`.pre-commit-config.yaml`](https://github.com/liatrio/engineering-bootcamp/tree/master/examples/company-app/milestones/M4-quality-automation/.pre-commit-config.yaml) and the *Rules* and *Commands* sections of its [`AGENTS.md`](https://github.com/liatrio/engineering-bootcamp/tree/master/examples/company-app/milestones/M4-quality-automation/AGENTS.md).

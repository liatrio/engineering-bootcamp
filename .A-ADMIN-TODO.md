# Admin TODO: dependency automerge settings

> [!IMPORTANT]
> Repo admin: run these before merging this PR, then delete this file in the final commit.

These steps change repo settings, which the PR author cannot do without admin rights. Run each command as a repo admin with the `gh` CLI. Each step has a GET command to confirm the result.

## 1. Enable auto-merge

Why: Renovate's `platformAutomerge` uses GitHub-native auto-merge, so a PR merges as soon as its required checks pass.

UI: Settings → General → Pull Requests → "Allow auto-merge".

```bash
gh api -X PATCH repos/liatrio/engineering-bootcamp -F allow_auto_merge=true
```

Verify:

```bash
gh api repos/liatrio/engineering-bootcamp --jq .allow_auto_merge
```

## 2. Create the ruleset in Evaluate mode

Rules: block deletion and force pushes, require a pull request with one approval, and require four status checks: `lint` (markdown-linter.yml), `test-front-matter` (test-front-matter.yml), `verify-actions-lock` (actions-lock.yml) and `playwright-test` (playwright-test.yml). The approval rule is the human gate for every change, including edits to `renovate.json` and `actions.lock`. The repo deliberately has no CODEOWNERS file, so repo settings and rules own this policy.

Renovate PRs that automerge need either a bypass entry for the Renovate app (Bypass list → add the "Renovate" GitHub App, mode "Pull request") or an approval from a human or another bot. Without one, the approval rule blocks automerge once the ruleset is Active. Rule Insights in Evaluate mode shows this before it bites.

Why: Evaluate mode lets Rule Insights show what would be blocked, so nothing breaks while `playwright-test` does not exist on `master` yet (it appears once this PR merges). Each check is pinned to `integration_id` 15368 (GitHub Actions) so another app cannot spoof it.

UI: Settings → Rules → Rulesets → New branch ruleset, named "master: dependency safety", Enforcement: Evaluate.

```bash
gh api -X POST repos/liatrio/engineering-bootcamp/rulesets --input - <<'JSON'
{
  "name": "master: dependency safety",
  "target": "branch",
  "enforcement": "evaluate",
  "conditions": { "ref_name": { "include": ["refs/heads/master"], "exclude": [] } },
  "rules": [
    { "type": "deletion" },
    { "type": "non_fast_forward" },
    {
      "type": "pull_request",
      "parameters": {
        "required_approving_review_count": 1,
        "dismiss_stale_reviews_on_push": false,
        "require_code_owner_review": false,
        "require_last_push_approval": false,
        "required_review_thread_resolution": false
      }
    },
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": false,
        "required_status_checks": [
          { "context": "lint", "integration_id": 15368 },
          { "context": "test-front-matter", "integration_id": 15368 },
          { "context": "verify-actions-lock", "integration_id": 15368 },
          { "context": "playwright-test", "integration_id": 15368 }
        ]
      }
    }
  ]
}
JSON
```

Verify:

```bash
gh api repos/liatrio/engineering-bootcamp/rulesets --jq '.[] | {id, name, enforcement}'
```

## 3. Flip the ruleset to Active

Do this after the PR merges and Rule Insights shows no unexpected blocks.

UI: Settings → Rules → Rulesets → "master: dependency safety" → Enforcement: Active.

```bash
gh api -X PUT repos/liatrio/engineering-bootcamp/rulesets/<id> -f enforcement=active
```

Verify:

```bash
gh api repos/liatrio/engineering-bootcamp/rulesets/<id> --jq .enforcement
```

## 4. Turn off Dependabot security PRs

Why: one bot, one policy. Keep Dependabot alerts on. Renovate's `vulnerabilityAlerts` opens the fix PR and a triage issue.

UI: Settings → Code security → "Dependabot security updates" off.

```bash
gh api -X DELETE repos/liatrio/engineering-bootcamp/automated-security-fixes
```

Verify:

```bash
gh api repos/liatrio/engineering-bootcamp/automated-security-fixes --jq .enabled
```

## 5. Optional, org admin: require a lockfile

Why: the "Require lockfile" Actions policy blocks any workflow run that no valid lockfile covers.

UI: Org Settings → Actions → Policies. Run `gh actions-lock --verify` first.
